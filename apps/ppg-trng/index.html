Parameter meanings and recommended use
Analysis profile

500k diagnostic uses 500,000 bits and a block-size condition that keeps the Block Frequency calculation within the 500k profile. NIST STS 1M comparison uses 1,000,000 bits and the official software-style block size of 128.

Bit source

Current extracted bits uses the bit stream currently generated by the Live monitor or Noise extractor. ADC0/ADC2/ADC3 filters retained bits by source, and Firmware ENCF uses only key bits received from the firmware.

Bits to test

Uses the newest N retained bits. It does not increase the bit count. If fewer bits are available, the actual count is smaller. Set this to the same target for method comparisons.

Block size

Block length M for the Block Frequency test. In the 500k profile, use M=8192 or larger so the block count stays below 100. In the NIST STS comparison profile, M=128 matches the official software-style setting.

Non-overlap library

Official m=9 tests all 148 patterns and Official m=10 tests all 284 patterns from NIST STS 2.1.2. Single custom pattern keeps the direct binary-template check for exploratory use.

Approx entropy m

Pattern length m for Approximate Entropy. Larger values examine longer patterns but require substantially more bits. Keep 10 for long captures.

Serial m

Pattern length m for Serial test. It compares overlapping pattern frequencies at lengths m, m-1, and m-2. Larger values are data-hungry; 10 is a practical default.

Linear block M

Block length M for Linear Complexity. Larger M gives longer complexity estimates but reduces the number of blocks. 500 is the standard practical setting for long captures.

Overlapping mode

Strict NIST uses the Rev.1a reference settings m=9 and M=1032. Exploratory allows alternate values and recomputes the Pólya-Aeppli expected distribution; it is not an official NIST profile.

Overlapping m / M

m is the run length of the all-ones template and M is the independent block length. Matches are counted at every 1-bit offset, including overlaps. The result reports blocks, discarded tail bits, and observed/expected cell counts.

Result interpretation

PASS means the test ran and p-value >= 0.01. CHECK means the test ran and p-value < 0.01. N/A means a required input-length or test precondition was not met, so no p-value was calculated.

Alpha = 0.01. The 500k profile is an exploratory short-sequence profile, not an official NIST 1M assessment. CHECK means the test ran and detected a deviation; N/A means the test could not be validly evaluated. Random Excursions still requires at least 500 complete zero-crossing cycles.

What this attack measures
Attack target

Predict the next bit from the preceding bit history. ADC0 and ADC3 are treated as non-biomedical ambient/optical noise sources in this analysis.

Models

Majority and Markov baselines are compared with logistic regression, a compact 1D CNN, and an RBF network using the selected history lag. The best predictor is highlighted in the summary.

Research mapping

1D CNNs are used in published PUF modeling attacks, while RBF kernels/networks are used for nonlinear PUF modeling. Here they are adapted to a time-ordered bit stream, not presented as a direct PUF-CRP reproduction.

Split rule

Training uses the earlier sequence and testing uses the final chronological holdout. Adjacent samples are never randomly mixed between train and test.

Interpretation

Accuracy above the majority baseline indicates predictability. This is an entropy-source diagnostic, not proof of a cryptographic break or security certification.

Reference method and interpretation
Preprocessing

The paper denoises, bins, and thresholds grayscale images upstream. The source-data MATLAB preprocessing then treats nonzero pixels as 1. This tab can apply that nonzero threshold to uploaded PNG/JPG/BMP files; ADC inputs must already be extracted binary responses.

MATLAB FOM

When the response length equals rows x columns, the tab reproduces Coding.m row-wise Hamming distance, row entropy, row uniformity, and similarity to the control response. Use 250 x 250 for the paper profile.

ML attack

The coordinate attack uses five independent CRP subsets and 10-70% training ratios. The added GFET paper uses Fourier regression orders 1, 2, 4, and 8; 75% reproduces 18 estimator CRPs from 24 experimental CRPs, while 80% matches its 0.8M/1M simulation profile.

Boundary

This is not a formal PUF security proof and does not replace SP 800-90B raw-source/min-entropy assessment. Temporal ADC blocks are only PUF-like responses after their challenge and repeat conditions are explicitly defined.

How to interpret this panel
Candidate threshold

SP 800-90B validation uses at least 1,000,000 sequential samples for the primary dataset. Shorter input is marked exploratory.

Entropy estimate

The browser reports MCV, Markov, and a t-tuple screening subset. The displayed subset minimum is conservative among those implemented estimates.

Health tests

RCT and binary APT are shown with alpha = 2^-20. They are failure detectors, not proof that the source has high entropy.

IID decision

Frequency, transition dependence, block stability, and autocorrelation are screening aids. Formal 90B IID determination requires the specified permutation tests.

Raw-source requirement

ADC0 and ADC3 bit streams are derived outputs. For a defensible entropy claim, capture and archive the raw ADC noise samples before bit extraction/conditioning.

Official reproduction

Use the Raw input button to export one byte per bit, then reproduce the result with NIST's official EntropyAssessment package.

Research context

Predictor and ML-based min-entropy diagnostics are used in recent TRNG research, but this panel keeps them supplementary to the NIST estimator minimum.
